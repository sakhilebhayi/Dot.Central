# Dot.Central: Requests to Dot.Mines

**Date:** 2026-10-15. Every item below was verified against the Dot.Mines code (`~/Dot/mines`) and is something Dot.Central works around today. Each entry says what Dot.Central does meanwhile and what would let it stop. These are proposals for the Dot.Mines maintainers; nothing here is assumed to exist.

| Ref | Request | Why | Dot.Central today | Proposed Dot.Mines change |
|---|---|---|---|---|
| I-28 (built 2026-10-15, Dot.Mines branch `feature/central-operators-api`, awaiting PR/merge there) | Publish operators and operator-to-machine assignments | The line-up assigns an operator per machine; Dot.Mines already holds operators, qualifications, medicals and an eligibility-gated assignment service | Per-room operator register and per-shift assignment in Dot.Central; no reconciliation | `operators` and `operator_assignments` scopes in `GET /api/v1/sync`; `POST /api/v1/machines/{id}/operator-assignments` and `DELETE …/{assignment}` calling `OperatorAssignmentService` so compliance checks apply; webhook events `operator.assigned` / `operator.unassigned` |
| I-30 (built 2026-10-15 on the same branch: `equipment_type` from the existing `EquipmentType` vocabulary instead of a new column) | A machine class field | `machine_type` is a brand (volvo, cat, komatsu, bell, ldv); the line-up needs loader / haul / support | Heuristic guess from model, manufacturer and capacity; administrator override | `machines.machine_class` (`loader`, `haul_truck`, `dozer`, `grader`, `drill`, `water_truck`, `service_truck`, `other`) on `MachineResource` and the `fleet` sync scope |
| I-01 (mitigated 2026-10-15: `integration:mint-token`; service account still proposed) | Service credentials | Tokens are minted by a human and die with that person's team membership | Human-minted token per connection, credential alerts | Client-credentials or service-account tokens scoped to a team with explicit abilities |
| I-23 (documented 2026-10-15; policy deliberately unchanged) | Token abilities should be enough for alert actions | `AlertPolicy` checks the user's role permissions, not the token's abilities; a token with `update` is refused | Refusal reported in the UI, event and audit | Honour token abilities for API callers, or document the required role and seed it for fixture teams |
| I-03 (built 2026-10-15) | Liveness on the machine resource | Provider cadence, last-heard time and stale flags are not exposed | Cadence configured per connection; freshness recomputed from metrics and location clocks | `last_heard_at`, `provider_cadence_seconds` and `stale` on `MachineResource` and the `fleet` scope |
| I-04 (built 2026-10-15) | Engine hours on the machine resource | `/sync` reads a column Dot.Mines never writes; real hours are per-metric | One `/machines/{id}/metrics` call per machine every 15 min | `operating_hours` and `operating_hours_recorded_at` from the latest metric on the resource and the `fleet` scope |
| I-06 (built 2026-10-15: `fuel_level_unit`) | Units | `fuel_level` is a percent from Bell but litres elsewhere; `speed` absent | Stored as reported, shown as "position only" | `fuel_level_unit` on metrics; `speed` when the provider supplies it |
| I-07 (built 2026-10-15) | OEM time on alerts | `triggered_at` is ingest time | Shown as "received by Dot.Mines at" | `source_triggered_at` on `AlertResource` and webhooks |
| I-20 (documented 2026-10-15) | Fixture team | The demo team owns no machines and its user has 2FA with a changed password | Live checks use the Bell end-to-end fixture team with a tinker-minted token and a hand-granted role | Seed the fixture owner with a team role and a documented token path |
| I-09 (resolved 2026-10-15) | Customer name in the Dot.Mines repo | `wiki.md`, `tests/Unit/BellServiceTest.php` and a fixture name carry a customer name | Not in Dot.Central (guarded by `ProhibitedReferencesTest`) | Generalise the names |
| I-05 / I-21 (built 2026-10-15: `WEBHOOKS_ALLOW_PRIVATE_URLS`, non-production only; first delivery verified) | Private webhook URLs refused | No end-to-end webhook proof locally | Signed-fixture tests | Allow loopback targets when `APP_ENV=local` |
